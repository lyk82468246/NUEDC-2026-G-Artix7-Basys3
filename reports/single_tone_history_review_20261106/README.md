## 历史单音确实成功

[2026-10-24实板记录](../../docs/component_amplitudes_hardware_20261024.md)明确给出已测试源码66632a3、bit/LTX哈希和实际单音结果：UTG CH1经原滤波器、AD9226进入FPGA，**B模式、连续测量**；100kHz单音两帧均为bin200、count1，槽位为[200,0,0]。FFT峰值参考50mV，换算51.243/51.239mV。Vpp约101.456/101.622mV，RMS约36.207mV。其参考值来自源设置，不是独立绝对电压校准。

所以不能将当前问题描述为“系统从未支持单音”。但也不能把当时B模式结果直接扩展为所有模式、所有信号源均已验收。当前严格锁定AFG设置的A模式对照为：原生SIN和EMEM纯正弦均被拒绝，GUI三音正常，见[11月5日对照](../single_tone_diagnostic_20261105/README.md)。早先另有一帧bin200结果，但缺少该笔采集前后源设置一致性证据，不把它单独认定为稳定回归通过。

## 核心算法没有近期修改

逐文件Git blob对照见[机器可读清单](blob_comparison.json)，比较66632a3与63c1688：以下8份RTL完全相同，相关FIR、FFT、CORDIC、平顶窗、MMCM及运行时VIO XCI也完全相同。

```text
Component_Analyzer.v   FFT_Processor.v     AFE_Capture.v
ADC_Input_CDC.v        Time_Domain_Calc.v  BRAM_TimeDomain.v
BRAM_FreqDomain.v      FlatTop_Window_ROM.v
```

算法IP目录生成文件差异也已检查：期间IP修改集中于ILA及新增Flash VIO，未发现上述算法IP产品变化。这是版本内容证据，不等同于两次布局布线、模拟输入、供电与外部ADC时序相同。

Component_Analyzer最后一次功能改动为88b72dd（10月23日），早于上述单音成功版本。因此目前没有证据把故障归为“近期修改了谱峰筛选算法”。

## 可疑处及优先级

### 1. 原有候选峰判决容易整帧否决：优先检查，尚非实板定论

最多三个候选先按幅度选出，排除每个候选左右6个bin，再按频率排序。第二/第三候选初始门限为max(64,最大幅值/256)，约为主峰0.39%；随后还须大于背景均值的8倍。最低频候选被当作基频，任一其他候选不满足整数谐波容差即清零基频并判无效。

单音留下两个候选空位，孤立杂峰可能占位；三个强谐波则能占满前三候选，弱杂峰不再入选。这与当前对照现象相容，但旧版使用同一算法也曾成功，说明还须检查输入谱或实际候选变化，不能凭现象认定算法回归。

已运行的仿真给出可复现例子：背景100、bin200幅值1600000，单峰通过；加入bin193幅值10000、bin207幅值8000后，三候选均过门限，排序后谐波一致性失败。此例证明可能机制，不表示实板杂峰就是193/207。

63c1688将原来被清零的诊断槽改为可观察原始候选，metadata bit7标记schema3。新实板数据若count>0且资格失败，优先核对候选是否为非谐波；若count=0，转查谱幅度、背景过滤和FFT数据。这个“原始”仍是现有门限过滤后的候选，不是完整FFT。

### 2. 新HMI与旧版的配对RMS差异：真实边界风险，当前解释力较低

5b6d650引入Display_HMI默认分支。旧HMI先锁存谱有效性，再在消费配对结果时用vrms_latched判断门限；新分支将`spectral_valid && vrms_out >= MIN_SIGNAL_RMS`在peak_result_valid时锁存为pending_signal，使用实时RMS。

如果谱结果早于本帧时域结果，新分支可能锁存上一帧低RMS造成的无效判断；即使随后本帧RMS正常，也不会重新判断。此差异值得在后续加固中消除，但当前时序不支持直接认定它为根因：Time_Domain_Calc每点3拍，共约24576拍，加CORDIC；FFT输入每点至少READ_REQUEST/PREPARE/WINDOW_MULT/SEND四拍，共至少32768拍，随后还有FFT处理/输出和谱峰扫描。正常无异常停顿时，时域结果应明显先到。

当前实板RMS为644～1607，远高于门限64；要用这个风险解释现象，还必须证明时域结果实际迟到或跨帧，不能只看代码中存在实时读取就下结论。

### 3. 新HMI邮箱的同时到达风险：确有差异，未证明发生

旧HMI消费旧配对结果时，`have_time_result <= time_result_valid`与`have_peak_result <= peak_result_valid`保留同拍到来的新事件；新HMI在消费时无条件清空have_time/have_peak。若旧配对已就绪且新结果在该边沿到达，新pending数据会写入，但其标志可能被后面的清零覆盖。

受控采集在显示排空后才放行下一帧，正常情况下不应出现这种跨帧重叠。这个缺陷更可能表现为等不到配对/超时，不足以直接解释当前连续提交无效帧。capture_start同拍优先清空邮箱也有明确边界，须结合帧归属判断，不能盲目保留上一帧事件。

### 4. 显示周期锁相：不支持作为当前帧拒绝的直接原因

2d1a877加入显示基波相位/周期细化，7d0a24b加入带限插值，0bec807仅拆分Amax扫描流水线。它们读取HMI独立时域BRAM副本，在谱结果和时间结果已锁存、measurement_valid发布之后才执行。

Display_HMI的source_valid和signal_valid_out仅在复位或消费pending配对时赋值，波形锁相/插值阶段不再回写它们。没有发现从显示细化输出反馈至FFT数据或谱峰资格的连线。ADC采集前的过零触发是另一条路径，其源码仍与已测版本一致，仍不能仅因显示顺序而全面排除模拟/采样问题。

### 5. 复位、Flash及实现差异：启动问题另列，不能混为单音判决

c6b70a5为ADC CDC、AFE、时域、FFT、分析器和HMI增加等延迟的局部复位寄存器。c922b31在启用持久化时让BtnC仅复位算法、保持MMCM/Flash控制器运行，并在恢复完成前禁止新采集。这些改变启动/复位边界，但未发现“只对单音”生效的分支。

Run_Controller自66632a3以来仅增加显示请求输出，采集状态机及释放方程未改。新HMI忙时禁止开始采集；AFE只在WAIT_CROSS检查capture_enable，不会因此把一帧采到一半截断。冻结帧、显示重绘和采集许可已有回归检查。

当前资源占用远高于历史47/50 BRAM、12862 LUT版本；不同布局布线和未独立验收的外部ADC约束仍是实物差异，RTL相同不能证明输入采样无误。此前USB连接时启动未完成（DONE/EOS=0）属于另一件已观察到的问题，不能用于解释当前已运行程序里的单音/多音差异。

## 下一步顺序

1. 完成当前63c1688用户构建并加载匹配LTX，确认metadata bit7=1，避免用旧诊断格式作结论。
2. 同一HIGHZ、100kHz单音分别抓A和B模式新帧，B模式与历史成功条件对照；C搜索范围与B相同，但仍单独确认模式元数据。
3. 读取候选count/bins/magnitudes，再决定是否需要修订候选选择/一致性规则。先不为获得读数而扩大容差或降低阈值。
4. 若判决前候选正确而HMI仍无效，重点检查谱有效性、时域就绪与邮箱；上述两处配对/邮箱风险可在证据明确后单独加固并加顺序碰撞测试。
5. 单音稳定通过后再恢复幅值拟合、独立幅度验证与VIO应用；当前标定记录未改写。
