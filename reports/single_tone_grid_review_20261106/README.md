# 单音散点失效：频点扫描与真实ROM时序审查

2026-11-06。用户补充：单音200mVpp，从10kHz以1kHz步进至约50kHz，略少于一半频点有正常示数，分布零散，回忆中似乎没有相邻两个正常点；未保留频点表，模式也未确定。本报告不把回忆升级为精确奇偶规律。板子当时已断电，本轮没有USB/JTAG操作、信号源操作、综合/实现/下载，也没有修改用户正在构建的生产RTL、IP或XPR。

## 新线索意味着什么

固定幅度下，普通低通滚降更容易形成随频率逐渐变化的误差，而不是频点交错地失效。因此提高了以下问题的优先级：索引/数据相关的RTL运算、弱谱峰是否被当作候选、其与基波的整数关系、以及实际ADC/信号源杂散随采样比例变化的情况。

1kHz步进对应名义FFT索引20、22、24……100，均为偶数；若真有隔点规律，应检查的是bin模4、8等关系，不能简单称为“奇数bin失败”。实际采样率约4.0960452MHz，对应500.0055Hz/bin；本频段偏离理想整数bin约0.00022～0.00110bin，正常平顶窗不应仅由这点偏差导致一半频点失效。

缺少具体正常/失败频点，也不知道重复测试同一频点是否稳定，尚不能区分真正奇偶规律、固定杂峰的谐波关系、相位依赖或偶发采样问题。

## 246个实际RTL分析器案例

入口：`scripts/run_single_tone_grid_review.ps1`。脚本仅生成离线向量并运行XSim；真实Component_Analyzer状态机和同步读BRAM接口参与测试，FFT向量由标准库浮点参考模型生成，不是Xilinx XFFT/CORDIC逐位仿真。

每个10～50kHz频点分别测试A/B模式、三类数据，共41×2×3=246例：

| 数据 | 通过数 | 含义 |
| --- | --- | --- |
| 理想量化正弦+现有Q1.15平顶窗 | 82/82 | 所有频点count1、索引正确；未复现分析器bin奇偶/进位错误 |
| 同上，但窗系数故意滞后一个采样 | 82/82 | 此理想模型中，窗错位不足以复现散点失效 |
| 主峰+假设的160kHz固定窄带杂峰 | 20/82 | 谐波判决能产生零散通过/失败；不代表实板有此杂峰 |

理想采样模型采用近似实测采样率4.0960452MHz、零相位、ADC正弦峰值227码、量化后放大8倍近似当前raw幅度；这些是模型参数，不是电压标定，不包含真实模拟噪声、FIR全精度内部截断或XFFT蝶形舍入。独立预期是已知单音频率，而不是从RTL自行计算一个“应有结果”再互相比对。

假设杂峰案例为背景100、主峰1600000、160kHz/bin320处杂峰10000；两者均过现有门限。两模式下通过频点都是：10、12、13、16、18、20、23、27、32、40kHz。这**包含相邻12/13kHz，且仅10/41通过**，不完全匹配用户回忆，不能宣称已经重现相同统计分布。它仅证明“零散失效”不必来自索引位错误，也可由既有一致性算法对固定杂峰作出不同判断。

逐点模拟结果见[CSV](simulated_grid_results.csv)，XSim结果见[摘要](grid_simulation_result.txt)。原始向量在忽略的`test_results/single_tone_grid_review_20261106`，可由脚本重建。

## 确认一个真实缺陷：平顶窗ROM的使能/延迟契约不符

此项使用仓库真实的`flat_top_window_rom_sim_netlist.v`及unisim RAMB36E1模型，不是单拍ROM替身。入口：`scripts/run_flattop_rom_latency_review.ps1`。

XCI启用了`Register_PortA_Output_of_Memory_Primitives=true`，实际模型中的RAMB36E1为DOA_REG=1。尽管生成属性还标注C_READ_LATENCY_A=1，实际脉冲使能行为不能据该标签猜测。测试显示，像FFT_Processor当前ST_READ_REQUEST那样只给一次ENA，然后在ST_PREPARE取数，会得到上一次使能请求的系数；后续ENA=0的空等拍不推进输出寄存器。

```text
请求地址512：   ST_PREPARE读到0000，正确系数ff53
请求地址1280：  ST_PREPARE读到ff53，正确系数fa3f
请求地址2048：  ST_PREPARE读到fa3f，正确系数f8ff
```

8个跳变地址均复现上一请求数据。测试的DOUBLE_ENABLE=0“PASS”表示**成功复现缺陷**，不是当前接口正确。实际FFT源码亦仅在ST_READ_REQUEST使能ROM，在随后的ST_PREPARE锁存系数；顺序扫描时因此将样本i与系数i−1配对，首帧第一个系数为输出初值。

另一个测试将同一地址连续使能两拍，再在第三个上升沿锁存，8个跳变地址均得到正确系数。实际记录见[ROM模型trace](actual_rom_trace.txt)。该测试验证了修正时序方案，**尚未将修正应用到生产FFT_Processor**。简单加一个ENA仍为0的WAIT状态不够。

建议后续修订方式为：READ_REQUEST → 新READ_WAIT（同地址继续使能ROM）→ PREPARE → WINDOW_MULT；时域BRAM只请求一次并保持读数据不变。这样不改ROM IP参数、不增加DSP/BRAM，每个输入样本多1拍，一帧增加8192拍=81.92µs。必须再用实际ROM和FFT输入监视验证全部样本配对、首末地址及AXI背压，才能称为生产修复完成。

此缺陷在10月24日已测单音成功的旧版也存在，源码和IP产品均未变化。上述理想错位窗扫描也全部通过，所以当前不能声称它解释了一半频点失败。它是确证应修复的问题，但“缺陷存在”和“当前故障根因”须分开。

## 进一步RTL核对

- XFFT XCI为nonrealtime、natural_order、8192、unscaled，未发现误配实时吞吐或倒序输出；没有变更这些配置。
- 分析器在本频段的12位索引、无符号幅值比较、排除区间和整数谐波容差已由上述246例实际RTL检查。检查未覆盖所有实际FFT数值和输入时序，不能宣布所有数据相关错误已排除。
- 新旧HMI配对RMS与同时到达邮箱风险仍见[历史复核](../single_tone_history_review_20261106/README.md)，目前没有新增证据证明它们触发。
- 显示周期锁相仍位于本帧资格判决之后，不直接修改FFT数据；采集前过零触发与真实ADC噪声/失真仍未由此排除。

下一步仍应读取63c1688的新原始候选快照，最好记录至少一对相邻正常/异常频点，并重复相同频点。若拒绝时存在非谐波弱候选，就能直接检验上述杂峰假设；若主候选本身错误或count0，则转查FFT/采样。当前标定系数和Flash记录均未修改。
