# Flash 标定参数持久化实施方案

日期：2026-10-30。本文是实施设计，不代表功能已经实现或完成实板验证。

P0记录格式、NOR断电模型与MCS地址审计已实现；P1只读SPI、记录解码/选择、可选板级VIO诊断已实现并通过行为仿真。

最新13:12参考构建实际为BRAM47.5/50、DSP90/90、LUT17267/20800，不是最初计划采用的47/89基线。

## 目标与当前基础

首次加入持久化功能并完成一次构建、烧录后，后续通过 VIO 调参、应用、保存即可更新标定数据，无需修改 RTL 或重新综合、布局布线。保留现有无 MCU 架构。

当前 Runtime_Calibration 支持默认系数、VIO staging/request/ack 和包间原子提交；默认系数作为恢复后备。当前没有 Flash 参数控制器。2026-10-30 构建使用 LUT 14948/20800、BRAM 47/50、DSP 89/90，因此新增逻辑优先采用串行 SPI 和分拍状态机，不增加 DSP。用户已确认允许适量增加 BRAM，以时序收敛和可靠性为优先；第一版允许增加 1 个 BRAM Tile 用于页/读回缓冲，寄存器保存活动系数和事务快照，不强制推断 BRAM。实际增量及 setup/hold 以完整实现报告为准。

## P0：确认硬件与冻结存储协议

- 确认真实 Flash 丝印、JEDEC ID、容量、擦除粒度、页尺寸、保护位、最大操作时间和指令集。PIC24FJ128GB106 是辅助 MCU，不是目标 Flash。
- 对照板卡原理图确定 CS/DQ 引脚，CCLK 使用 STARTUPE2；核对现有约束不冲突。先用标准 SPI x1，启动/退出时恢复芯片规定的安全空闲状态。
- 建议 4MB 地址空间中 0x000000–0x3DFFFF 为程序预留区，0x3E0000–0x3EFFFF 为参数 A，0x3F0000–0x3FFFFF 为参数 B。两份各预留 64KiB，实际擦除命令按芯片确定，不能据此假设它支持 64KiB 擦除。
- 这是候选分区：确认芯片容量与擦除对齐后冻结。构建脚本须检查镜像实际覆盖范围，禁止与参数区相交；不能只看压缩 bit 文件长度。
- 固定记录字节序和 CRC 算法：建议小端、CRC-32/ISO-HDLC；用共享测试向量验证 RTL 与主机实现。
- 记录建议为固定 64 字节，含 magic、格式版本、长度、序号、算法/单位兼容标识、enabled、Vpp/RMS/FFT 三个 uint32 Q16.16 系数、保留字、CRC、独立提交标志。CRC 覆盖范围和各字段偏移须在编码前形成逐字节规范。
- 参数标识反映系数语义，不以每次 bit 构建哈希为兼容判据。改变单位、增益定义或数据结构时升级兼容标识。

出口：型号和协议核对记录、确定的分区与二进制格式；此阶段不擦写 Flash。

## P1：SPI 控制器与只读启动恢复

增加 Flash_SPI_Master（字节事务）、Flash_Command_Engine（ID/读/写使能/状态轮询/页编程/擦除）和 Calibration_Store（记录、A/B 调度、恢复）。模块名称可随仓库习惯调整。

先只实现 ID、读状态和读数据，接 STARTUPE2。全部状态机使用 100MHz 主时钟与时钟使能，SPI 时钟由寄存器分频产生，不新增内部逻辑时钟域。对 MISO 采样相位和 I/O 时序单独约束、验证，不能使用一律 false-path 掩盖。

上电读取 A/B，仅接受已提交、CRC 正确、格式/算法兼容且字段合法的记录。按带回绕定义的序号规则选择最新记录；相同序号但数据不同视为冲突并报告。无有效记录使用现有 RTL 默认值，并报告来源与错误原因。

在 Runtime_Calibration 前增加提交仲裁：启动恢复优先，完成后才开放 VIO 提交。所有来源仍通过包间原子提交路径更新，维护原有每包 epoch 快照，避免 VIO 默认 staging 覆盖恢复系数。显示使用同一活动系数源。

在首次测量前完成恢复或有界超时回退；恢复期间显示准备状态，不输出看似有效的旧系数测量。BtnC 后重新读取已保存数据，不自动保存未持久化编辑；Flash 事务的处理见 P2。

出口：空 Flash 回退、A/B 选择、CRC/版本拒绝、首次测量、VIO 后续覆盖均通过仿真；硬件只读识别与记录读取正确。

## P2：在线保存与掉电保护

保留 rc_apply 的易失更新语义，新增显式 save 操作。保存捕获已经应用且 ack 确认的完整活动 bank 和 epoch，而不是抓取可能变化的 VIO staging。

保存流程：检查 idle/合法性与地址范围 → 比较已保存内容（相同则跳过擦写）→ 擦除非当前有效槽 → 页边界内写入正文与 CRC → 读回逐字节及 CRC 校验 → 单独编程提交标志 → 再次读取确认提交有效 → 更新保存状态。提交标志位置需满足芯片关于同页多次编程的限制，否则调整记录布局或提交策略。

始终保留旧有效槽，下一次成功保存才轮换。每条擦除、编程、状态写入命令在底层校验目标地址范围与操作覆盖范围；不提供整片擦除命令。未知 JEDEC ID/保护状态或状态轮询超时均进入明确错误状态，不盲目重试。

保存进行时拒绝新的 apply/save/reload；测量可继续使用捕获前的活动 bank，Flash 模块使用独立缓冲，不争用算法 BRAM。BtnC 不复位 Flash 事务控制器，期间延后参数重载；上电复位与面板复位需分开。真正断电由 A/B 协议恢复；重新连接/上电须处理芯片可能仍忙的情况。

VIO 协议增加 command、request/ack、busy、完成码、保存序号、保存的 epoch、参数来源、JEDEC ID 和错误状态。状态须能区分已应用未保存、保存中、保存成功、保存失败。新增事务沿用 toggle 握手并处理面板复位后的旧 toggle，不以短脉冲跨 JTAG 提交。

出口：页编程、擦除、超时、读回失败、写入期间复位及断电注入通过模型验证；实板单次保存和重启恢复通过。

## P3：主机工具与固件更新保护

扩展现有 Tcl 库，提供计划接口 rc_store_status、rc_save、rc_reload、rc_export；具体命名实施时统一。rc_apply 不自动写 Flash。保存接口明确返回持久化结果及读回系数，不用 VIO apply 的 ack 代替 Flash 保存完成。

主机超时后报告状态未知，先查询硬件事务和存储状态，不自动重复擦写。导出 JSON 记录系数、单位/兼容版本、序号、CRC、时间、板卡标识和构建标识，便于恢复与追踪。此阶段不增加任意地址写入接口或批量导入功能。

增加程序区 MCS 生成和审计脚本：从地址 0 放入启动镜像，检查最高地址及按实际擦除粒度向外对齐后的范围不进入参数区。记录输入 bit 哈希、输出 MCS 哈希和 Flash 型号。

升级说明明确禁止 Entire Configuration Memory Device/整片擦除；使用经过审计的仅程序区域擦写流程。硬件验证升级前后参数区字节保持一致，并冷启动验证参数确实恢复。首次安装可以使用默认系数启动，然后通过在线 save 建立参数记录。

出口：应用/保存/重载/导出流程可复现；更新启动镜像后标定数据保留。

## P4：验证与交付

仿真覆盖：空白、单份有效、双份有效、CRC 错误、格式不兼容、非法零增益、序号回绕/冲突、忙时重复命令、VIO 重连及面板复位。Flash 模型强制检查 WREN、忙状态、页边界、擦除范围及 NOR 只能 1→0 编程语义。

在每个擦除/正文编程/提交/读回阶段注入掉电。期望恢复旧完整记录或新完整记录；首次保存中断允许回退默认值，不接受半写记录。目标保护是更新事务的断电一致性，不承诺芯片损坏或同时损坏两槽时仍保留数据。

集成验证：包间原子切换、显示和测量系数一致、首包有效性、epoch、BtnC 恢复已保存值、未保存值掉电丢失。验证保存期间采集/显示行为；记录上电恢复时间及其对启动两秒指标的影响。

构建验证：综合资源增量、全实现 setup/hold、DRC、配置引脚约束、新 bit/LTX 配对。当前 DSP/BRAM 余量有限，不以功能仿真替代完整实现。

实板验收：ID 与丝印一致 → 默认启动 → apply A → save A → 真断电启动恢复 A → apply B 不保存并断电恢复 A → save B 并断电恢复 B → 参数区保持的程序升级 → 实板受控中断保存测试。受控断电测试在基础读写和离线故障注入通过、备份启动镜像和参数之后开展。

交付包括 RTL、XDC、VIO IP/匹配 LTX、Tcl 工具、模型/测试、MCS 审计脚本、使用说明、实板记录。第一版只保留两槽和最后一次已保存标定，不引入文件系统、MicroBlaze、磨损均衡日志或多套用户配置。

## 实施顺序

P0 → P1 仿真和只读板测 → P2 模型验证及实板保存 → P3 更新保护 → P4 完整验收。读写控制器和记录协议可在仿真中先完成；实际写入必须等待 Flash 型号及擦除规则确认。首次构建完成后，日常重新标定无需修改 RTL 或重新实现。
